THE MODEL

One main spine. Two complements. No course overload.

MAIN SPINE

The Construct

Use it for robotics-specific Python/C++/Linux foundations, then ROS 2, TF, URDF, Navigation, ros2_control and hands-on simulated/remote robot work.

COMPLEMENT 1

Official ROS ecosystem docs

Use ROS 2, Nav2 and Gazebo documentation to verify APIs, architecture and current best-practice behavior. This is your authoritative technical reference.

COMPLEMENT 2

Modern Robotics

Use Northwestern's book/videos selectively when the software exposes a math gap: frames, transformations, kinematics, Jacobians, planning and control.

Rule: The Construct tells you how to build it. Official documentation tells you what the software actually expects. Modern Robotics helps you understand why the robot mathematics works.

PHASE 2 — AI / CODEX SUPERVISION

After the sprint, change the relationship with AI.

BEFORE ROS You write most of the code.

Use AI mainly for explanations, debugging hints, quizzes and review.

MONTH 1 You design the ROS graph.

AI may implement bounded nodes, but you inspect callbacks, interfaces and tests.

MONTH 2 You specify subsystems.

AI can implement larger pieces; simulation and official docs verify behavior.

POST-SPRINT You direct architecture.

Codex accelerates implementation while you retain interface, safety, test and acceptance authority.

What you must be able to specify

  • node responsibility
  • input/output topics or actions
  • message types
  • QoS / timing expectations
  • failure behavior
  • test criteria
  • safety boundaries

What you must be able to review

  • Python/C++ structure
  • ROS graph and interfaces
  • logs and diagnostics
  • simulation behavior
  • Git diff / PR
  • tests
  • unsafe shortcuts

Architecture you should reject

LLM / agent
      ↓
direct motor command

Language-model output should not directly control safety-critical actuators.

   ↓
